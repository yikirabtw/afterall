# Тиммейты и компании на вечер

Telegram-бот и мини-приложение для поиска тиммейтов и компаний на вечер.
План работ — `docs/ROADMAP.md`, устройство базы — `docs/DATABASE.md`.

## Структура
```
backend/
  app/
    config.py         настройки (DATABASE_URL, BOT_TOKEN, WEBAPP_URL, порт API, CORS)
    api/              API на FastAPI для мини-приложения: вход по initData, маршруты, схемы
    bot/              Telegram-бот на aiogram: хендлеры, мидлвари, тексты, клавиатуры
    db/               модели SQLAlchemy, перечисления, подключение к базе
    domain/           бизнес-логика (пока — расчёт возрастной группы)
    services/         операции с базой, общие для бота и API (регистрация пользователя)
  migrations/         миграции Alembic
  scripts/            служебные скрипты (заполнение справочника игр)
  tests/              тесты
webapp/               мини-приложение: Vue 3 + Vite + TypeScript
  src/
    api/              клиент API, типы, тексты ошибок
    views/            экраны: онбординг, лента, мои пати, профиль
    components/       карточка пати
    telegram.ts       обёртка над Telegram Mini Apps SDK
    styles.css        дизайн-токены и общие стили
docs/                 дорожная карта и описание базы
```

## Первый запуск (Windows, PowerShell, из папки backend)
```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.\.venv\Scripts\alembic.exe upgrade head
.\.venv\Scripts\python.exe -m scripts.seed_games
.\.venv\Scripts\python.exe -m pytest -q tests
```
Без файла `.env` база создаётся в `backend/dev.db` (SQLite).
Для PostgreSQL скопируйте `.env.example` в `.env` и пропишите `DATABASE_URL`.

## Запуск бота
1. В Telegram откройте @BotFather → `/newbot` → придумайте имя и юзернейм бота → скопируйте токен.
2. В папке `backend` создайте файл `.env` (можно скопировать из `.env.example`) и впишите:
   ```
   BOT_TOKEN=токен_от_BotFather
   ```
   Токен — это пароль от бота: никому не показывайте его и не выкладывайте в открытый доступ.
3. Из папки `backend`:
   ```powershell
   .\.venv\Scripts\python.exe -m app.bot
   ```
4. Напишите боту `/start`. Остановить — `Ctrl+C`.

Когда появится мини-приложение, добавьте в `.env` строку `WEBAPP_URL=https://...` — у бота появятся
кнопка «Открыть приложение» и кнопка меню.

## Запуск API
Нужен тот же `BOT_TOKEN` в `backend/.env`: им проверяется вход из мини-приложения. Из папки `backend`:
```powershell
.\.venv\Scripts\python.exe -m app.api
```
API работает на http://127.0.0.1:8000, документация с кнопками для проверки — http://127.0.0.1:8000/docs.

**Как работает вход.** Telegram при открытии мини-приложения передаёт ему `initData` — строку,
подписанную токеном бота. Мини-приложение отправляет её в каждом запросе заголовком
`Authorization: tma <initData>`. API проверяет подпись и срок (по умолчанию 24 часа),
регистрирует пользователя при первом входе и отклоняет забаненных.

| Маршрут | Вход | Что делает |
|---|---|---|
| `GET /api/health` | не нужен | проверка, что API жив |
| `GET /api/me` | нужен | вход: свои данные, анкета, игры, расписание и `is_onboarded` |
| `GET /api/games` | нужен | справочник игр с рангами и ролями |
| `PUT /api/me/birth-date` | нужен | дата рождения → возрастная группа; задаётся **один раз** |
| `PUT /api/me/profile` | нужен | анкета; заменяется целиком (не переданные поля — по умолчанию) |
| `PUT /api/me/search-age` | нужен | возраст поиска в ленте людей `{"age_min", "age_max"}` (null — до рамки); рамки — в `GET /api/me` → `search_age_limits` |
| `PUT /api/me/games` | нужен | список игр с рангом и ролями; заменяется целиком, до 10 игр |
| `PUT /api/me/availability` | нужен | когда играю: слоты по дням недели в минутах; заменяется целиком |
| `POST /api/me/onboarding/complete` | нужен | завершить онбординг (нужны дата рождения, анкета и хотя бы одна игра) |

Все `PUT` и `complete` возвращают свежие данные пользователя — то же, что `GET /api/me`.

**Ошибки входа:** `401 missing_init_data`, `401 invalid_init_data`, `401 init_data_expired`, `403 banned`.

**Ошибки онбординга** (в `detail`):
- `409 birth_date_already_set` — дату рождения меняет только поддержка;
- `422 too_young` — младше минимального возраста, ничего не сохранено;
- `422 unknown_game`, `rank_not_in_game`, `role_not_in_game` — игра, ранг или роль не подходят;
- `422 {"code": "onboarding_incomplete", "missing": [...]}` — чего не хватает для завершения;
- неверный формат полей — стандартная ошибка FastAPI 422 со списком полей.

### Пати
Все маршруты — только после онбординга (иначе `403 onboarding_required`).

| Маршрут | Кто | Что делает |
|---|---|---|
| `POST /api/lobbies` | любой | создать пати (в игру или `hangout` — «просто посидеть») |
| `GET /api/lobbies` | любой | лента: `game_id`, `kind`, `language`, `play_style`, `fits_me`, `cursor`, `limit` |
| `GET /api/lobbies/mine` | любой | мои пати: созданные, принятые и с откликом |
| `GET /api/lobbies/{id}` | любой | карточка пати |
| `POST /api/lobbies/{id}/apply` | любой | откликнуться (`{"note": "..."}` — по желанию) |
| `POST /api/lobbies/{id}/leave` | участник | отозвать отклик или выйти |
| `POST /api/lobbies/{id}/members/{user_id}/accept` | создатель | принять |
| `POST /api/lobbies/{id}/members/{user_id}/decline` | создатель | отклонить |
| `POST /api/lobbies/{id}/members/{user_id}/kick` | создатель | убрать принятого |
| `POST /api/lobbies/{id}/cancel` | создатель | отменить пати |

**Правила:**
- пати видна только своей возрастной группе; при блокировке в любую сторону и у забаненного создателя — не видна (404);
- контакты — `contact_link`, `username`, `discord_tag` — видят только создатель и принятые;
- `contact_link` — только `https://t.me/...` или Discord-приглашение;
- старт — не позже чем через сутки, пати живёт 3 часа от начала;
- при заполнении статус `full`, освободилось место — снова `open`;
- отклонённый или выгнанный не может откликнуться снова, вышедший сам — может;
- лимиты: 2 активные пати и 10 откликов на ожидании на человека.

**Ошибки:** `404 lobby_not_found`, `403 not_lobby_owner`; `409` — `too_many_active_lobbies`,
`too_many_applications`, `lobby_full`, `lobby_not_active`, `already_applied`, `application_declined`,
`kicked_from_lobby`, `cannot_apply_own_lobby`, `owner_cannot_leave`, `not_a_member`, `member_not_pending`,
`member_not_accepted`; `422` — `unknown_game`, `party_too_big`, `rank_not_in_game`, `invalid_rank_range`,
`starts_at_out_of_range`, `mic_required`, `rank_out_of_range`.

### Фото профиля
| Маршрут | Что делает |
|---|---|
| `POST /api/me/photos` | загрузить фото (multipart, поле `file`; JPEG/PNG/WebP до 10 МБ, не больше 3 фото) |
| `DELETE /api/me/photos/{id}` | удалить своё фото |
| `PUT /api/me/photos/order` | порядок своих фото `{"photo_ids": [...]}`, первое — главное |
| `GET /api/photos/{id}?e=…&s=…` | само фото по подписанной ссылке (без входа) |

- Сервер поворачивает фото по EXIF, уменьшает до 1280 px и сохраняет JPEG **без EXIF** — в снимках с телефона
  там бывают GPS-координаты. Фото лежат в базе (на бесплатном Render диск стирается при перезапуске).
- `<img>` не умеет слать `Authorization`, поэтому API отдаёт фото подписанными ссылками (живут 6–12 часов)
  только тем, кому их можно видеть. Ник — до 20 символов, «о себе» — до 150.
- Ошибки: `409 too_many_photos`, `422 photo_too_large / photo_format_not_supported / photo_unreadable`,
  `422 photo_order_mismatch`, `404 photo_not_found`.

### Люди (лента анкет) и мэтчи
| Маршрут | Что делает |
|---|---|
| `GET /api/people` | анкеты своей возрастной группы, по убыванию «совпадения»: `game_id`, `need_mic`, `play_style`, `language`, `limit` |
| `POST /api/people/{user_id}/react` | `{"kind": "like" \| "skip"}`; при взаимном лайке в ответе `match` с контактами |
| `GET /api/matches` | взаимные лайки с контактами, новые сверху |
| `DELETE /api/matches/{user_id}` | удалить мэтч у обоих (204); личный чат уходит вместе с ним, человек больше не появится в ленте |
| `POST /api/reports` | жалоба `{"user_id", "reason", "comment"?, "lobby_id"?}` на мэтч или участника общей пати (204): сразу блокирует, уходит модераторам в бот; 10 в сутки |
| `GET /api/blocks` | кого я заблокировал |
| `POST /api/blocks/{user_id}` / `DELETE /api/blocks/{user_id}` | заблокировать / разблокировать (204) |

**Уведомления в боте** (`app/services/notify.py`): мэтч — тому, кто лайкнул первым; сообщение — кто не заходил
в приложение 45 с, одно на чат до прочтения; отклик на пати — создателю; «приняли / не взяли» — откликнувшемуся.
Кнопка открывает нужный экран (`?open=chat/direct/12`). Шлёт только сервер (бот в режиме вебхука);
локально уведомления пишутся в лог. Жалобы приходят модераторам (роль в базе) и админам из
`ADMIN_TELEGRAM_IDS` (`123456789`, несколько — через запятую) — с кнопками «Бан на 7 дней / Навсегда / Отклонить».

- **«Совпадение N%»** — `domain/people.py`: общие игры (35, +5 за каждую следующую, до 40), общая основная 10,
  близкий ранг 10, стиль 15, цели 10, язык 5, микрофон 10. Плюс до трёх причин «почему вам по пути».
- Не показываются: другая возрастная группа, скрытые анкеты, забаненные, блокировки в любую сторону, уже лайкнутые.
  Пропущенные возвращаются через 3 дня.
- Контакты — только в мэтче: `discord_tag`, если указан; `username` (ник в Telegram) — только если человек
  включил «Показывать мой Telegram» (`show_telegram` в анкете). Иначе общаются в чате приложения.

### Тарифы (ветка dev)
`GET /api/me` → `plan`: `{"plan": "free" | "plus" | "premium", "until", "photos_max", "active_lobbies_max"}`;
в ленте и мэтчах у человека `plan` — для значка у ника. Лимиты: фото 1 / 3 / 3 (загруженные раньше остаются),
открытых пати 2 / 5 / 10. Выдать подписку — админ пишет боту: `/premium` (себе на 30 дней), `/premium 7`,
`/premium @ник 30`, `/premium <Telegram ID>`, `/plus …`, `/free @ник` — снять; `/premium ?` — подсказка.
`GET /api/people/likes` — кто поставил мне ♥, а я ещё не ответил (правила как у ленты): `{"count", "people"}`,
`people` — только с Plus и Premium, бесплатно `null` (ни имён, ни фото).

### Чаты
| Маршрут | Что делает |
|---|---|
| `GET /api/chats` | все переписки: мэтчи и пати, где тебя приняли (закончившиеся — ещё 7 дней); непрочитанные, последнее сообщение |
| `GET /api/chats/{direct\|lobby}/{ref}` | переписка (ref — id собеседника или пати); `after` — только новые (опрос), `before` — старые страницы; отмечает прочитанным |
| `POST /api/chats/{direct\|lobby}/{ref}/messages` | `{"body": "..."}` до 1000 символов; не больше 30 сообщений в минуту; в закончившейся пати — `chat_closed` |

- Писать можно только мэтчам и участникам своей пати; блокировки и баны закрывают переписку.
- Новые сообщения клиент забирает опросом раз в 3 секунды (на бесплатном сервере это проще, чем держать соединения).

### Боты для разработки ленты (только локально)
`python -m scripts.dev_bots create [--count 60]` — случайные анкеты в возрастной группе `dev_tester`, часть заранее
лайкает его (лайкни в ответ — будет мэтч и чат); `reset` — лента заново; `remove` — удалить ботов.

## Мини-приложение
Нужен Node.js (стоит LTS 24). Первый раз, из папки `webapp`:
```powershell
npm install
```

**Разработка в обычном браузере.** Вне Telegram у страницы нет initData, поэтому вход подменяется
тестовым пользователем `dev_tester` (не вашим аккаунтом):
1. Запустить API (см. выше).
2. Из папки `backend`: `.\.venv\Scripts\python.exe -m scripts.dev_init_data` — запишет вход в
   `webapp/.env.development.local` (действует 24 часа, потом повторить).
3. Из папки `webapp`: `npm run dev` → http://127.0.0.1:5173. Запросы к `/api` dev-сервер сам
   передаёт на API (порт 8000).

Пройти онбординг заново: `.\.venv\Scripts\python.exe -m scripts.dev_init_data --reset` из `backend`.
Если правка в коде не подхватилась — перезапустите `npm run dev`.

**Проверка и сборка:** `npm run typecheck`, `npm run build` (результат — папка `webapp/dist`).

**Что есть сейчас:** вход по initData, онбординг из 3 шагов (возраст → анкета → игры с рангами и ролями).
Вкладки: **Пати** (лента с фильтрами и переключатель «Все пати | Мои»), **Люди** (анкеты на весь экран со
свайпом, «Совпадение N%», фильтры под ⋮, мэтчи под ♥), **Профиль** (шапка с фото на треть экрана, карандаш →
редактирование: до 3 фото, ник, описание и остальная анкета). Создание пати, экран пати: отклик с сообщением,
решения создателя (принять, отклонить, убрать, отменить), контакты и «Перейти в чат» для принятых.
Тема берётся из Telegram (светлая и тёмная), фирменный акцент — мятный.

**Открыть внутри Telegram (для тестов — через туннель Cloudflare).** Telegram открывает мини-приложения
только по публичному HTTPS-адресу. Бесплатный туннель без регистрации даёт такой адрес на время:
1. Должны работать API и `npm run dev` (см. выше).
2. В отдельном терминале: `cloudflared tunnel --no-autoupdate --protocol http2 --url http://127.0.0.1:5173`.
   В выводе появится адрес вида `https://слова-через-дефис.trycloudflare.com`.
3. Вписать его в `backend/.env`: `WEBAPP_URL=https://....trycloudflare.com` и перезапустить бота.
4. В Telegram у бота появятся кнопка меню «Открыть» и кнопка под ответом на `/start`.

Адрес меняется при каждом запуске туннеля — тогда повторить шаги 3–4. Тестовый вход `dev_tester`
по адресу туннеля не работает (только на `127.0.0.1`), войти можно только из Telegram.
Если туннель не поднимается с ошибкой `context deadline exceeded` — сеть до Cloudflare нестабильна,
запустите ещё раз.

**На текущей сети туннели Cloudflare заблокированы провайдером** (проверено 27.10.2026): поиск серверов
через DNS не работает, при прямом указании адресов (`--edge`) TCP-соединение есть, но TLS обрывается (`EOF`),
QUIC не проходит вовсе. Работает только с VPN на компьютере или через другой сервис туннелей / свой сервер.

## Бесплатный хостинг: Render + Neon
Пока нет потока людей — всё на бесплатных тарифах. Один контейнер (`Dockerfile`) содержит API, бота и
собранное мини-приложение; база — бесплатная PostgreSQL в Neon (на Render бесплатная база удаляется через 30 дней).

**Как это работает на сервере:**
- Render сам передаёт адрес сервиса (`RENDER_EXTERNAL_URL`). Раз адрес есть — бот работает через **вебхук**:
  Telegram присылает обновления на `/telegram/webhook`, отдельный процесс бота не нужен.
- Мини-приложение отдаётся по `/`, API — по `/api`, адрес приложения = адрес сервиса.
- При каждом старте: миграции базы → справочник игр → API (с регистрацией вебхука и кнопки меню).

**Один раз:**
1. Neon (neon.com): создать проект в регионе Frankfurt (AWS eu-central-1), скопировать строку подключения
   `postgresql://...` (Connection string).
2. GitHub: положить код в приватный репозиторий (`.env`, `dev.db`, `node_modules` туда не попадают — см. `.gitignore`).
3. Render (render.com, вход через GitHub): New → Blueprint → выбрать репозиторий. Render прочитает `render.yaml`
   и попросит ввести `BOT_TOKEN` и `DATABASE_URL` (строка из Neon).
4. После первого деплоя у бота появятся кнопка меню «Открыть» и кнопка под ответом на `/start`.

**Ограничения бесплатного тарифа:**
- Сервис засыпает после 15 минут без запросов и просыпается около минуты — первое сообщение после паузы бот
  обработает с задержкой. Лечится «будильником»: бесплатный сервис вроде cron-job.org раз в 10 минут открывает
  `https://<адрес>/api/health` (750 бесплатных часов в месяц хватает на один сервис без сна).
- База в Neon — до 1 ГБ.

**Важно:** пока бот работает на сервере, локально `python -m app.bot` с тем же токеном не запустится
(он видит вебхук и останавливается, чтобы не увести бота с сервера). Для локальной разработки заведите
отдельного тестового бота в @BotFather.

## Тестовая копия (ветка dev)
Основа — ветка `main`: её видят живые люди в @afterall67_bot, Render выкладывает её при каждом push.
Новое делаем в ветке `dev` и проверяем в отдельном тестовом боте; в `main` переносим, когда всё проверено.

**Один раз:**
1. @BotFather → `/newbot` → тестовый бот (например, `afterall_dev_bot`), сохранить его токен.
2. Neon → свой проект → Databases → New Database (например, `afterall_dev`) и скопировать строку подключения
   именно к ней. Отдельная база — чтобы проверки не трогали данные живых людей.
3. Render → New → Web Service → тот же репозиторий, ветка **dev**, Docker, регион Frankfurt, план Free.
   Health Check Path — `/api/health`. Переменные: `BOT_TOKEN` (тестового бота), `DATABASE_URL` (база `afterall_dev`),
   `ADMIN_TELEGRAM_IDS` (`[ваш Telegram ID]`). Render сам выкладывает `dev` при каждом push в эту ветку.
4. После первого деплоя у тестового бота появится кнопка «Открыть» — это копия приложения.

**Тестовые боты в копии:** впишите в `backend/.env` строку `STAGING_BOT_TOKEN=<токен тестового бота>`
(только в файл, в чат и в git — нет), затем из `backend/`:
`python -m scripts.staging_bots create --like "*"` — 40 ботов 18–30 лет (`--ages`), часть ставит ♥ живым людям
копии (или `--like "Имя из анкеты"`),
часть создаёт пати; `... lobbies` — свежие пати (живут 3 часа); `... hide` — убрать ботов из ленты.
Подпись токеном тестового бота основа не примет — боты не попадут к живым людям.

**Бесплатные часы Render (750 в месяц) общие на все сервисы.** Копию «будильником» не будить — она спит, когда
её не проверяют, и почти не тратит часы. Если основу держать без сна круглые сутки, это ~744 часа — тогда копию
лучше включать только на время проверок (Suspend / Resume в панели).

## Изменить схему
1. Поправить модели в `backend/app/db/models/`.
2. `.\.venv\Scripts\alembic.exe revision --autogenerate -m "что изменилось"`
3. Проверить созданный файл в `migrations/versions/`.
4. `.\.venv\Scripts\alembic.exe upgrade head`

`alembic.ini` должен оставаться только на латинице: на Windows Alembic читает его в системной кодировке.
